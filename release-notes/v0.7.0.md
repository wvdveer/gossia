# Gossia 0.7.0: form canvases

Gossia 0.7.0 lays forms out the way reports are laid out: as a stack of
canvases with controls placed exactly. It also makes HTML exports of reports
much smaller and lets formulas read dates with `strptime`.

## Form canvases

Every form is now a stack of **sections**, one under the other, each as wide
as the form, with its own height and its controls at fixed places. The
sections are a **form header**, a **repeater** for each list shown on the
form, a fixed **section** between two repeaters, and a **form footer**.
Groups on a section still arrange their own controls as Flow, Grid or Free.

- **Repeaters.** A repeater section shows one row per item of an array, all
  of them, drawn as its canvas. Inside a row, paths are read from the item.
  Only the rows on the screen are drawn, so a long array scrolls as easily as
  a short one.
- **The row number.** Every repeater has a row name (`row`, `row2`, ...).
  Inside a row it is that row's number from 0; elsewhere it is the current
  row, the one that last had the focus, marked by a bar on its left. In
  expressions it is `context.row`, so a label with the template
  `{context.row + 1}` numbers the rows.
- **Master and detail.** Paths can use row names and context fields in
  brackets: `orders[row].lines` shows the lines of the current order.
- **Context fields** are fields whose value belongs to the form, not to the
  data: a name, a type and a default, in the form header. They choose what
  the rest of the form shows (`items[sel].name`), are `context.<name>` in
  expressions and `ctx.context.<name>` in procedures, and are remembered with
  the workbook.
- **Adding and deleting rows.** An **add/delete button** in a repeater gives
  each row a Delete button and a blank row at the end, filled in and added
  with Add. Alternatively, a **row mark** puts a checkbox in each row, and a
  **rows button** in the header or footer adds a row, deletes the marked
  ones, or marks them all. Procedures read the marks as `ctx.marked`.
- **The designer** is the report designer's, for forms: the sections with
  their names on the left, dragging their heights and the form's width,
  dragging controls from one section to another, and *Add repeater*.
- **Editing a form.** A form shows no strip above it any more: start editing
  with **View > Forms > Edit form**, and leave with the **Finish edit**
  button. A report has an **Edit report** button, which becomes **Finish
  edit** in the report editor.
- **Labels with a width.** A label with a width of its own puts its text
  where its alignment says inside that width, and the designer shows and
  selects it by that box, not by the text it happens to show.
- **The generated form** is built as canvases: the fields that are not in a
  list in the header, and each array as a repeater with a row of fields, the
  column titles above it, and an add/delete button.
- **Older designs** are turned into canvases the first time they are opened.
  The stepper and the tables inside forms are gone: a context field and paths
  that use it do what the stepper did, and sorting, filtering and hiding rows
  stay in the data tree.

## Smaller HTML exports

A report exported as HTML now embeds each font reduced to the characters the
report uses, at the regular and bold weights it uses, in place of the whole
fonts. The export of a small report goes from about 1.3 MB to under 60 KB. The
browser draws no kerning in the export, but every line keeps the width it has
in the PDF.

## Other changes

- **`strptime` in formulas.** `datetime.strptime(text, format)` reads a date
  or time from text by a format, as `strftime` writes one.
- The GitHub workflows use actions that run on Node 24, since GitHub retires
  Node 20, and each release is copied to a release page on the Gitea mirror.
